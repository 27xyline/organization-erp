# Архитектура приложения

Project1 Accounting — модульный монолит на Next.js App Router. Код сначала
разделяется по предметным областям, а затем — по ответственности внутри каждого
модуля.

## Модули

- `assets` — имущество, движения и справочники МОЛ/групп;
- `employees` — сотрудники, штат, отпуска и кадровые действия;
- `projects` — проекты, задачи и участники;
- `finance` — финансовые планы и проектный payroll;
- `users` — пользователи и смена пароля;
- `exports` — формирование выгрузок.

## Слои feature-модуля

```text
src/features/<feature>/
├── contracts/       Zod-схемы, DTO, UI-модели и подписи
├── domain/          чистые бизнес-правила и доменные ошибки
├── application/     запросы, команды и транзакционные сценарии
├── infrastructure/  сложные Prisma-запросы и helpers (только при необходимости)
└── ui/              React-компоненты и hooks предметной области
```

Пустые слои не создаются. Простые CRUD-сценарии могут использовать Prisma из
application-слоя; repository-интерфейсы вводятся только при наличии реальной
вариативности или повторного использования.

## Направление зависимостей

```text
app ───────────────► feature/application ─────► feature/domain
 │                              │
 └───────────────► feature/ui    └────────────► feature/infrastructure ─► lib/prisma

feature A ───────► feature B/contracts
```

Правила:

1. `src/app` содержит только маршрутизацию, авторизацию, HTTP-адаптацию и
   композицию экранов.
2. `src/lib` содержит общую инфраструктуру и не зависит от `features` или `app`.
3. Domain-код не зависит от application, infrastructure, UI, Next.js и Prisma
   client.
4. UI не обращается к Prisma и infrastructure напрямую.
5. Один feature не импортирует внутренние слои другого; межмодульный обмен идёт
   через `contracts`, а композиция нескольких features выполняется в `app`.
6. Внутри feature используются относительные импорты. Абсолютный alias `@/`
   применяется для общей инфраструктуры, UI-kit и публичных contracts другого
   модуля.

## Стабильные внешние границы

HTTP URL, методы, JSON-ответы, роли, Prisma-схема и клиентские сценарии являются
внешними контрактами. Архитектурный рефакторинг не должен менять их поведение.
