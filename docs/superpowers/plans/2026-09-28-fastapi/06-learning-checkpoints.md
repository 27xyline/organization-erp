# Учебные паузы: что разбирать после каждого этапа

Паузы — часть переноса. Агент не продолжает по таймеру, молчанию пользователя или потому, что соседняя задача «почти готова». Пользователь может задержаться на любом этапе, попросить объяснение или самостоятельное упражнение.

## Формат завершения этапа

1. Показать один работающий сценарий и фактические проверки.
2. Составить маленькую схему пути запроса с реальными именами файлов.
3. Объяснить новое понятие на этом сценарии, начиная с простого примера.
4. Показать изменённые файлы и 2–3 места, которые стоит читать первыми.
5. Дать небольшое упражнение; сначала пользователь пробует сам, агент помогает по запросу.
6. Записать в progress результат и статус «ожидает учебного разбора».
7. Остановиться до явного сообщения «переходим к этапу N».

Не нужно запоминать всю кодовую базу. Нужно уметь найти правило, объяснить его, изменить и подтвердить тестом.

## Карта остановок

| Этап | Что изучить | Вопрос для проверки понимания | Самостоятельное упражнение |
|---|---|---|---|
| 00 | API-контракт и существующий request path | Какие изменения сломают frontend даже при status 200? | Проследить один route до SQL и обратного JSON |
| 01 | FastAPI, lifespan, Depends, settings, pytest fixtures | Кто создаёт/закрывает DB pool и как тест подменяет config? | Добавить техническое поле в live response и contract test |
| 02 | ORM vs domain, session/UoW/transaction, async eager load | Что останется в БД при исключении между двумя insert? | Написать rollback regression test |
| 03 | Authentication, authorization, scopes, bridge | Почему подписанного user ID недостаточно после отзыва сессии? | Тест denied access к чужому department |
| 04 | Полный request path по общей слоистой структуре | Почему router не делает SELECT и commit? | Добавить фильтр подразделений через все нужные слои |
| 05 | Кадровые инварианты и atomic workflow | Какие таблицы меняются при увольнении и что откатывается? | Правило валидности даты сертификата с тестом |
| 06 | Graph dependencies и бизнес-валидация | Как обнаружить цикл и почему это domain? | Проверка cross-project dependency |
| 07 | Concurrent writes и locks/retries | Почему два запроса могут списать один остаток дважды? | Тест двух независимых sessions на списание |
| 08 | StoragePort, SHA, версии, FS+DB consistency | Почему rollback PostgreSQL не удаляет файл автоматически? | Тест damaged download или failed promote |
| 09 | State machine, decision conflict, notification intent | Когда approval считается изменённым, а письмо ещё не отправлено? | Тест повторного решения одного шага |
| 10 | Decimal, rounding, period lock | Что случится при close и edit одновременно? | Изменение расчёта на copy fixture с expected Decimal |
| 11 | Составной use case и idempotency | Как asset и delivery link оказываются в одном commit? | Тест повторной капитализации |
| 12 | Aggregates, scope filtering, N+1, rendering | Почему total нельзя считать по первой странице? | Ускорить SQL-запрос и измерить до/после |
| 13A | Outbox lease, retries, SMTP at-least-once | Может ли письмо повториться после падения и почему? | Crash/reclaim тест |
| 13B | Метрики/traces/logs | Чем «процесс запущен» отличается от «очередь обрабатывается»? | Воспроизвести queue delay и найти её на dashboard |
| 14A | Alembic baseline/handoff | Что stamp делает и чего не делает? | Проверить миграцию на новой disposable DB |
| 14B | Python session/CSRF/cookie | Почему HttpOnly cookie не решает CSRF сама по себе? | Тест expired/revoked session |
| 14C | Cutover/rollback и restore | Какие изменения делают старый TS backend несовместимым? | Пройти runbook восстановления на copy |
| 14D | Поддержка проекта и архитектура | Где изменить правило, не меняя HTTP и SQL код? | Реальное небольшое domain/service изменение с тестом |

## Эталон для чтения кода

Первым читать модуль подразделений этапа 04 в таком порядке:

```text
app/api/routes/departments.py     — как запрос приходит
app/schemas/departments.py        — что приходит и что возвращается
app/services/departments.py       — последовательность действий
app/domain/departments/rules.py   — почему действие допустимо
app/domain/ports/departments.py   — какие данные нужны сценарию
app/repositories/departments.py  — как данные читаются/записываются
app/models/departments.py        — как объект хранится в PostgreSQL
app/db/uow.py                    — почему изменения атомарны
tests/integration/departments/   — доказательство поведения
```

Эти пути пока проектные: файлы появятся при выполнении соответствующего этапа.

## Команды для диалога

> Объясни выполненный этап на одном реальном запросе: вход → router → service → domain → repository → БД → ответ. Покажи файлы и причину каждой границы. Следующий этап не начинай.

> Дай мне маленькую задачу на текущий модуль без готового решения. Сначала только условия и ожидаемое поведение; затем проверь мой код.

> Выполни только этап N из соответствующего плана. В конце запусти его проверки, запиши результат в progress, объясни код и остановись.

## Критерий личного результата

Можно без подсказки открыть нужный service, понять transaction boundary, изменить правило, написать meaningful test и объяснить альтернативу. Готовый сгенерированный проект сам по себе этот критерий не подтверждает.
