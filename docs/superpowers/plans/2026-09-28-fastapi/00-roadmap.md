# План постепенного переноса backend на FastAPI

Дата: 28 сентября 2026. Статус: план подготовлен; ни один этап реализации не начат.

**Цель:** весь backend на Python с сохранением frontend и с обязательными паузами для обучения.

**Архитектура:** один backend с общими слоями `api/schemas → services → domain`; `repositories`, `models`, `db` и `integrations` реализуют инфраструктуру через `domain/ports`. Папки соответствуют скриншоту пользователя.

**Основной стек:** Python 3.13, FastAPI, Pydantic 2, SQLAlchemy 2.x, PostgreSQL 15, Alembic, uv, pytest, HTTPX, Ruff, mypy; позднее Python OpenTelemetry для существующего мониторинга.

**Архитектурный документ:** [решения и ограничения](../../specs/2026-09-28-fastapi-backend-design.md). Это проект для обсуждения; создание плана не запускает реализацию.

## Как читать и выполнять

1. Начать с этого файла и архитектуры.
2. Выполнять один этап за раз, включая проверки и подключение реального frontend.
3. На паузе разобрать код и выполнить упражнение из [учебных остановок](06-learning-checkpoints.md).
4. Следующий этап начинается только по явной команде пользователя.
5. Обновлять [прогресс](08-progress.md) после выполнения; не отмечать проверки, которые не запускались.

Каждая волна имеет отдельный план. Внутри крупных этапов можно остановиться после одной подзадачи; запрещено объединять несколько этапов в один неограниченный запуск.

## Что считать «полностью перенесено»

- [ ] Каждая строка реестра API/SSR/writers имеет Python-владельца или обоснованно удалена с заменой frontend.
- [ ] Сохранились роли, scope grants, forced password change, audit, правила денежных операций и согласований.
- [ ] Файлы документов сохранены, версии и SHA-256 проверены.
- [ ] Python единственный владелец бизнес-операций; Next.js содержит UI и тонкие HTTP-адаптеры.
- [ ] Alembic создаёт схему с нуля и принимает проверенную существующую копию.
- [ ] pytest, архитектурные проверки, frontend проверки и Playwright проходят.
- [ ] Метрики показывают HTTP/SQL/worker; отказ Collector, сбои SMTP и повтор outbox проверены.
- [ ] Restore из backup выполнен на отдельном окружении.
- [ ] Пользователь может самостоятельно изменить правило и объяснить путь запроса.

## Что пользователь добавит самостоятельно

Redis, Celery и другие отсутствующие технологии не являются зависимостями переноса. Идеи и критерии их добавления находятся в [самостоятельных расширениях](09-future-exercises.md). Структура backend соответствует скриншоту: общие `app/api`, `services`, `repositories`, `models`, `schemas`, `domain`, `db`, `core`, `integrations`, `tasks`.

## Бюджет и модели

Сначала измерить токены/итерации на 01 и 04. Прошлая оценка «1–5 миллионов и выше» — грубый диапазон без пилота; это не квота и не обещание завершить за такой расход. Различать input/cached input/output/reasoning и лимиты подписки.

Рекомендация: Sol для архитектуры, первого эталонного модуля, auth/транзакций и финальных проверок; Luna High для ограниченных задач по уже проверенному образцу. xhigh включать при конкретной трудности. Не поручать Luna одним сообщением весь документ. На старте очередного этапа читать архитектуру, его план, прогресс и только связанные файлы. Тестовые результаты сохранять кратко.

План не создаёт новые чаты, ветки и коммиты автоматически. Если пользователь попросит отдельную ветку, подготовить её перед реализацией. При смене модели можно продолжать в том же чате с явным номером этапа.

## Команда для начала

> Выполни только этап 00 из плана `docs/superpowers/plans/2026-09-28-fastapi/01-foundation.md`. Прочитай архитектуру и прогресс. Подготовь реестр текущих контрактов и writers. Не начинай этап 01. В конце покажи результат, объясни его и остановись для моего разбора. Не создавай ветки, коммиты и subagents без моего отдельного запроса.

Для следующих этапов заменить номер и файл. Продолжение всегда ограничивается одним этапом.
