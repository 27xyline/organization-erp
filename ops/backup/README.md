# Резервные копии PostgreSQL и документов

Команды выполняются из корня проекта на Linux или macOS. Нужны Python 3.13+
и работающий Docker Compose. Если Python установлен через `uv`, вместо `python3`
можно использовать `uv run --project backend python`.

## Создание

```sh
python3 ops/backup/erp_backup.py create
```

Команда создаст закрытый каталог `backups/erp-<дата-UTC>` с тремя файлами:
`database.dump`, `documents.tar.gz`, `manifest.json`. Манифест содержит время,
версию образа PostgreSQL, размеры и SHA-256 обоих архивов. Каталог доступен
только владельцу, файлы имеют права `0600`. Секреты `.env` в архив не добавляются;
сама база и документы могут содержать конфиденциальные данные.

Для согласованной копии команда кратко останавливает **только запущенные**
`app`, `worker` и `backend`, выполняет `pg_dump` и копирует хранилище документов.
Затем она возвращает остановленные сервисы в работу и дожидается готовности.
На это время приложение недоступно. Перед запуском завершите другие локальные
CLI-команды и внешние задания, которые могут писать в ту же БД или хранилище:
утилита управляет только сервисами данного Compose-проекта.

Частичный архив не публикуется. При ошибке утилита также пытается возобновить
ранее запущенные сервисы. Если процесс был принудительно убит или Docker
недоступен, проверьте `docker compose ps -a` и вручную запустите нужные сервисы.
Параллельные операции из этого checkout блокируются файлом `.backup.lock`.

Можно задать каталог явно; существующий каталог не перезаписывается:

```sh
python3 ops/backup/erp_backup.py create --output backups/before-update
python3 ops/backup/erp_backup.py verify backups/before-update
```

Для регулярных копий запускайте `create` планировщиком своего сервера в окно
обслуживания. Готовые копии переносите в отдельное защищённое хранилище:
каталог на том же диске не спасает при потере сервера. Каталоги `backups/`
и `.restore/` исключены из Git.

## Проверка восстановления

Восстановление разрешено только в **новый отдельный Compose-проект** и новые
volumes. Существующий проект или хранилища не перезаписываются. Используйте
ту же версию приложения и совместимую версию PostgreSQL, что при создании копии.
Восстанавливайте только свои доверенные дампы: SQL-дамп содержит исполняемые
команды PostgreSQL.

```sh
python3 ops/backup/erp_backup.py restore backups/before-update --project erp-recovery
```

Перед созданием ресурсов проверяются SHA-256 и безопасность путей в tar-архиве.
Утилита создаёт `.restore/erp-recovery/compose.json`, PostgreSQL и отдельное
хранилище документов, восстанавливает данные и запускает проверки `verify_schema`
и `verify_data`. Последняя проверяет в том числе наличие, размер и SHA-256
каждой версии документа. Успешный результат — все счётчики проблем равны нулю.
При ошибке отдельное окружение сохраняется для диагностики, исходное приложение
продолжает работать.

Для ручной проверки восстановленного интерфейса:

```sh
docker compose -p erp-recovery -f .restore/erp-recovery/compose.json up -d --wait
```

Откройте `http://127.0.0.1:3101`; учётные записи и пароли взяты из копии.
API доступен на `127.0.0.1:8101`, PostgreSQL — на `127.0.0.1:5541`.
Порты можно изменить флагами `--app-port`, `--backend-port`, `--postgres-port`.
Привязка остаётся локальной. Пароль PostgreSQL и CSRF-секрет генерируются заново.
Worker из проверочного окружения исключён, чтобы восстановленная очередь не
отправляла реальные письма повторно.

Всегда передавайте `-p erp-recovery`: явное имя защищает от случайного
`COMPOSE_PROJECT_NAME` в окружении или `.env` исходного проекта.
`compose.json` содержит настройки отдельного окружения и имеет права `0600`.
Это окружение предназначено для проверки восстановления; переключение пользователей
на него и production-настройки выполняются отдельно.

После проверки удалите **только проверочное окружение**:

```sh
docker compose -p erp-recovery -f .restore/erp-recovery/compose.json down --volumes
```

Исходные volumes и архив останутся. Чтобы повторно использовать имя `erp-recovery`,
после удаления его ресурсов удалите также каталог `.restore/erp-recovery`;
либо выберите новое имя для следующей проверки.

## Тесты

```sh
python3 -m unittest discover -s ops/backup -p 'test_*.py'
```

Проверяются повреждение архивов, небезопасные пути и ссылки, изоляция проекта,
отказ от восстановления в исходный проект и возобновление сервисов при сбоях.
