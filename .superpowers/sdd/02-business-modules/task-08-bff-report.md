## Implementation and ownership

- All seven Next document route modules now proxy to the frozen Python endpoints. Permission checks, query/body validation, request IDs, typed envelopes, URL escaping, and source error behavior stay at the BFF boundary. Upload/version/download routes pass raw request/response streams; metadata and source content length are forwarded only for raw document streams. Browser credentials and hop-by-hop headers are excluded. Download forwarding retains content-disposition, ETag, size, MIME, request ID, private/no-store, and `nosniff`.
- Generic JSON backend requests keep their existing eight-second timeout. The document transport has an eight-second idle deadline while uploading and awaiting headers, refreshed for each upload chunk; after response headers arrive the timer is cleared while body streaming and client cancellation remain connected. Focused transport tests cover a valid slow upload (chunks span the deadline), delayed download chunks, header timeout, and cancellation.
- Document index/detail SSR and project workspace documents now use authenticated Python reads with runtime envelope/pagination checks; individual item DTOs remain compile-time typed and rely on the frozen Python contract. Existing UI callers continue to use the same Next routes and DTOs.
- Migrated TypeScript document services, domain policies/templates/renderers, writable storage adapter and their superseded tests were removed. A narrow read-only storage adapter remains for `/api/health/ready` and `scripts/verify-data.ts`. Approval status/lockVersion writes remain in their existing transaction; procurement and global-search retain metadata-reader ownership, as scoped by Stage 08.
- `prisma/demo-seed.ts` is the one explicit fixture-only TypeScript writer exception. Its dedicated helper keeps UUID shard paths inside a real configured root, writes mode-0600 temp files, syncs them, and promotes with an atomic exclusive hard link so an existing key is never overwritten. It is not imported by application/runtime routes. Retaining the one-time demo seed preserves existing seeded relations; it is not an alternate runtime document service.
- Compose `backend` now receives `DOCUMENT_STORAGE_ROOT=/var/lib/project1/documents` and the same `project1_document_data` mount as `app`. Container build and isolated owned-volume permission/font checks remain pending below.
